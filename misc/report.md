# Отчёт по разработке бэкенда приложения для отслеживания расходов

## 1. Введение

В рамках данного задания был разработан бэкенд для приложения управления личными и групповыми финансами. 
Приложение предназначено для учёта доходов и расходов пользователей, анализа финансовых данных, а также совместного ведения бюджета в группах (например, семейных).

Цель работы — спроектировать модель данных, разработать REST API для основных функций приложения, обеспечить аутентификацию пользователей, а также подготовить инфраструктуру для развёртывания и тестирования сервиса.

---

## 2. Требования к системе

### 2.1 Функциональные требования

- регистрация, авторизация и аутентификация пользователей;
- добавление, редактирование и удаление финансовых транзакций;
- разделение транзакций на доходы и расходы;
- группировка транзакций по категориям и временным периодам;
- просмотр аналитики по личным и групповым расходам;
- создание и управление группами пользователей;
- экспорт данных в форматы CSV и XLSX.

### 2.2 Нефункциональные требования

- REST-архитектура;
- безопасность хранения паролей (хэширование);
- использование JWT для аутентификации;
- поддержка контейнеризации с помощью Docker.

---

## 3. Архитектура приложения

Приложение реализовано по клиент-серверной архитектуре. Серверная часть представляет собой REST API, взаимодействующее с реляционной базой данных PostgreSQL. Для аутентификации используется механизм JWT (access и refresh токены).

Основные компоненты системы:

- модуль аутентификации и авторизации;
- модуль управления транзакциями;
- модуль аналитики;
- модуль управления группами;
- база данных.

---

## 4. Модель данных

### 4.1 Таблица пользователей (users)

Содержит данные, необходимые для регистрации и аутентификации пользователей:

- идентификатор пользователя;
- имя;
- фамилия;
- логин;
- хэш пароля;
- дата создания.

### 4.2 Таблица групп (groups)

Используется для объединения пользователей в группы:

- идентификатор группы;
- название группы;
- идентификатор владельца;
- дата создания.

### 4.3 Таблица участников групп (group_members)

Реализует связь многие-ко-многим между пользователями и группами:

- идентификатор пользователя;
- идентификатор группы;
- роль пользователя в группе.

### 4.4 Таблица категорий (categories)

Хранит категории доходов и расходов:

- идентификатор категории;
- название;
- тип (доход или расход);
- идентификатор пользователя.

### 4.5 Таблица транзакций (transactions)

Основная таблица финансовых операций:

- идентификатор транзакции;
- наименование;
- тип транзакции;
- сумма;
- дата;
- категория;
- пользователь;
- группа (опционально).

---

## 5. REST API

### 5.1 Аутентификация и авторизация

- POST `/api/auth/register` — регистрация пользователя;
- POST `/api/auth/login` — аутентификация;
- POST `/api/auth/refresh` — обновление токена;
- POST `/api/auth/change-password` — смена пароля.

### 5.2 Работа с транзакциями

- POST `/api/transactions` — создание транзакции;
- GET `/api/transactions` — получение списка транзакций (с фильтрацией и пагинацией);
- PUT `/api/transactions/{id}` — редактирование транзакции;
- DELETE `/api/transactions/{id}` — удаление транзакции.

### 5.3 Работа с группами

- POST `/api/groups` — создание группы;
- GET `/api/groups` — получение групп пользователя;
- PUT `/api/groups/{id}` — редактирование группы;
- DELETE `/api/groups/{id}` — удаление группы;
- GET `/api/groups/{id}/analytics` — аналитика по группе.

### 5.4 Аналитика

- GET `/api/analytics/categories` — аналитика по категориям;
- GET `/api/analytics/period` — аналитика по выбранному периоду.

- тесты регистрации и авторизации;

## 7. Развёртывание

Для развёртывания проекта используется Docker Compose, который включает контейнер с бэкенд-приложением и контейнер с базой данных PostgreSQL. Это позволяет обеспечить воспроизводимость окружения и упростить запуск проекта.
